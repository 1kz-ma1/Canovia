# V41.10 Adaptive Learning Flow — Phase A

## Goal

AI演習を「同じTaskで問題を繰り返す機能」から、学習結果に応じて安全にTaskを進めるフローへ拡張する。

Phase Aでは以下に限定する。

1. 採点後UIをPrimary Action中心へ整理
2. AIのTask完了提案をCanovia側で検証
3. 1回の高得点だけでTaskを跨がない
4. 仕上げ確認を通過したら次のeligible Taskへ進む
5. 次Taskの内容を新しいStudy Practice Strategy / Promptへ使う

学習Activityの多様化と演習信頼度表示はPhase Bで扱う。

## Completion Boundary

AIの `next_step.kind=complete_task` と `recommended_task_progress_percent=100` は、DB更新命令ではなく **completion signal** とする。

Canoviaの `StudyTaskProgressionService` が以下を判定する。

- `reinforce_current`
- `continue_current`
- `verify_mastery`
- `advance_task`
- `review_plan`
- `plan_complete`

### Mastery verification

Task完了には、直近2回が連続して以下を満たすことを要求する。

- score >= 85
- summary weaknessesが空
- incorrect / partial のうち重大なerror typeが残っていない

重大なerror type:

- knowledge_gap
- concept_gap
- reasoning_gap
- condition_reading
- unit_error
- unknown

`careless` と `calculation_slip` は、それ単独ではTask完了を阻止しない。

完了Signalはあるが検証不足の場合、進捗100%への自動反映を止め、最大99%で `mastery_verification` に移る。

## Next Task

仕上げ確認を通過した場合、CanoviaがPlan内から次に実行可能なTaskを選ぶ。

- done / cancelled / 100% は除外
- dependencyが未完了なら除外
- 現在Taskへのdependencyは、現在Taskを完了すると仮定して解放
- doing
- priority
- activation_cost
- sort_order
- id

の順で決定する。

AIはTask IDを選ばない。

## Result UI

Result画面ではPrimary mutationを1つだけ表示する。

未反映:

```
NEXT ACTION
...
[結果を反映して次へ]
```

詳細な強み・弱点・問題別Feedback・評価根拠は「詳しい評価を確認」へ折りたたむ。

Task反映用の第二CTAは廃止する。
