# V41.13 Action & Inbox Reframe

## Purpose

Canoviaの主要導線を、現在のExecution Tool / Evidence / Recall / Career基盤に合わせて再設計する。

旧来の「今日 = Taskを選んでTimerを開始する」中心設計から、

- Home = Now / 次に実行する
- Inbox = Input / 現実から取り込む
- Roadmap = Future / 先を見る
- Timeline = Past / 振り返る

へ責務を分離する。

V41.13は段階実装する。

---

## Step 1 — Action Hierarchy Cleanup

### Principle

1 Taskに対してPrimary Actionは原則1つ。

CanoviaがTaskに適した専用実行Toolを特定できるなら、そのActionだけをPrimary表示する。

専用ToolがないときだけTimerをFallbackにする。

### Primary priority

1. Study Activity
2. AI Practice
3. Career Workspace
4. Artifact
5. Resource
6. Timer fallback

判定は `ExecutionActionPolicyService` に集約し、Home / Today's Route / Plan詳細で同じPolicyを使う。

### UI cleanup

- AI演習 / Recall等がPrimaryならTimerを並べない
- Timer fallback時だけ「時間は目安」を出す
- Study Focusは判断材料専用にし、実行CTAをCurrent Taskへ集約
- Task ListからCurrent Taskを除き「このあと」を表示
- Active WorkSession中は「作業へ戻る」を最優先
- Plan詳細上部もCurrent TaskのPrimary Actionを使う
- 「計画を更新」は通常secondary、未反映状態のみ強調
- 無関係なPlanで0件のArtifact入口を常設しない
- Resource StudyでResource CTAとTimerを並べない

## Step 2 — Canovia Inbox Foundation

### Navigation

Main navigation:

```text
Home | Inbox | Roadmap | Timeline
```

`/navigate` は互換Routeとして残すが、Main Navigationからは外す。

### Inbox role

Inboxは「何かをCanoviaへ渡す共通入口」と「処理待ちを確認する受信箱」。

Initial inputs:

- text
- URL
- image / screenshot
- PDF

ユーザーに最初からTask / Resource / Recall / Evidence等の分類を要求しない。

### Model

必要なら最小の `inbox_items` を追加する。

Implemented states:

- new
- review
- processed
- archived

`review` is reserved for Step 3 routing / confirmation. Step 2 does not invent an AI processing state before intelligent routing exists.

既存のRecall Candidate / Career Capture / WorkSession等をInbox用に複製しない。
Inboxは既存pending stateを横断表示する。

Step 2 implementation:
- Recall Candidate: pending
- Career Capture: pending
- WorkSession: needs_plan_update
- private Inbox file route with identity authorization
- Main Navigation changed to Home / Inbox / Roadmap / Timeline

### Entitlement

Step 2:
- capture is available without Automatic AI entitlement
- optional Plan association
- manual processed / archived state
- existing pending states are visible without duplication

Step 3:
- Native AI destination suggestion is an acceleration feature
- extraction / classification friction reduction remains behind the appropriate entitlement

## Step 3 — Inbox Intelligence + Guide v2

### Intelligent routing

Inbox inputから以下のdestination候補を1つ提示する。

- Future Memo
- Career Capture
- Recall Material
- Task Evidence
- Plan Resource
- Keep in Inbox

AIが返せるPlan / Task情報は名前のhintだけで、IDを返すschemaは持たない。
Plan ID / Task IDはHuman Review時にCanoviaの所有権境界内で人が選ぶ。

Suggestionは `InboxItem.metadata.routing_suggestion` へ保存し、状態を `review` にするだけで正規データを作らない。

Human Review後の確定先:

- Future Memo -> `FutureMemoService`
- Career -> `CareerCaptureService`
- Recall -> `StudyRecallCandidateExtractionService`
- Evidence -> `TaskEvidenceService`
- supported Resource URL -> Plan Resource
- Keep in Inbox -> `new` のまま

Freeでも手動routingは利用可能。
AI suggestionとRecall Candidate抽出だけ `AutomaticAiExecution` entitlement配下に置く。

Task Evidenceへ変換したInbox observationはconfidence 0.5とし、それ単独で進捗を自動加算しない。

Career screenshotはCareer側payloadへ独立保存し、Recall画像/PDFはStudy Recall Sourceへコピーする。
変換先をInbox元ファイルの寿命へ依存させない。

### Guide v2

Guide catalog versionを2へ更新し、旧v1の完了状態と分離する。

`today_action` を廃止し、Timerを通常導線ではなくFallbackとして説明する。

Guide v2 includes:

- Homeで次の行動を確認する
- Inboxに何か渡す
- Inboxを整理する
- AI演習で理解を確認する
- Recallで覚える
- 教材からRecallカードを作る
- 専用ToolがないTaskをTimerで進める
- 状況変化をPlanへ反映する
- Resource / Collaboration

Guide config version is incremented so completed-guide state is isolated from v1.

Do not automatically increment the account onboarding version only because Guide v2 changes.
Existing users should not be forced through onboarding again.

### New onboarding

新規オンボーディングは機能一覧ではなく主要な責務を教える。既存アカウントへ再表示しないため `canovia.onboarding_version` は上げない。

```text
Home
  "今やることはここ"
    ↓
Roadmap
  "先を見るならここ"
    ↓
Inbox
  "現実で起きたことや資料はここへ"
    ↓
Done
```

AI Practice / Recall / Timer are contextual Guide topics rather than required first-run steps.
