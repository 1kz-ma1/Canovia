# V40.7.4 Guided Study Flow

## Purpose

AI演習を「採点結果を見る機能」ではなく、
次の学習Actionまで途切れず進める伴走フローへ改善する。

V40.7.3までの画面は、

```text
問題
↓
回答
↓
評価Prompt
↓
評価JSON
↓
結果
```

を同一ページへ縦積みしていた。

そのためPOST / redirectのたびにページ下部へ移動する必要があり、
学習の集中を中断していた。

## UX Principle

AI演習では常に

> 今やることを1つだけ主役にする。

過去Stepは消さず、必要なときだけ展開できる。

## Stage Model

UI上の高レベルStage:

```text
1. 問題準備
2. 回答
3. AI評価
4. 結果・次Action
```

StudyPracticeSessionの既存statusを使って現在Stageを判断する。

- setup: 問題未準備
- answering: questionsあり / assessment handoff前
- evaluation: evaluation_promptあり / assessment未取得
- result: assessmentあり

新しいDB statusは追加しない。

## Current-step UI

### setup

主表示:

- Question Bank開始
または
- 外部AIへ問題作成Promptを渡す
- 問題JSONをCanoviaへ戻す

### answering

主表示:

- 問題
- 回答欄
- 「回答をまとめて評価へ進む」

途中回答autosaveはV40.7.1を維持する。

### evaluation

主表示:

- 評価Promptをコピー
- 評価JSONをCanoviaへ戻す

回答済み問題は:

```text
回答済み N問 · 回答を見直す
```

へ折りたたむ。

### result

最上部へ:

- NEXT ACTION
- 次に行うこと
- 理由
- focus topics
- question count
- Primary CTA

を表示する。

過去Step:

- 今回の回答
- AI評価の受け渡し

は折りたたみへ移動する。

## Structured next_step

External AI assessmentへ、従来のnext_actionに加えて
next_stepを必須で要求する。

```json
{
  "next_action": "CNAMEとAレコードを5問演習する",
  "next_step": {
    "kind": "practice",
    "label": "CNAMEとAレコードの使い分けを5問演習する",
    "reason": "レコード種別の使い分けに混同が残っているため",
    "focus_topics": ["DNS", "CNAME"],
    "question_count": 5
  }
}
```

Allowed kind:

- practice
- review
- continue_task
- complete_task
- plan_update

## Compatibility

next_stepがない旧assessmentも壊さない。

Canoviaが以下からfallbackを作る。

- next_action
- weaknesses
- recommended_task_progress_percent

例:

- weaknessesあり → practice
- progress 100% → complete_task
- その他 → continue_task

## Authoritative Boundary

AIは次に行う学習内容を提案する。

AIは以下を決めない。

- Plan ID
- Task ID
- route
- button action
- database mutation

Canoviaがnext_step.kindを安全なUI Actionへ変換する。

## Result CTA

### 未反映

Primary CTA:

```text
まず学習結果をCanoviaへ反映
```

Taskへ反映するまで進捗・next_action_noteは変更しない。

### 反映後 / practice

```text
この内容で次の演習へ
```

現在のbrowser stateを終了し、
直近Attemptを次のPractice Strategyへ渡す。

### 反映後 / plan_update

```text
学習結果をもとに計画を見直す
```

Plan Review Assistantへ進む。

### その他

Plan / Taskへ戻って次の行動へ進む。

## Next Practice Handoff

next_step.kind = practice の場合、
次回StudyPracticeStrategyへ:

- focus_topics
- question_count

を引き継ぐ。

Strategyは直近weakness / misconceptionもmergeし、
AIが指定したtopicだけに完全依存しない。

例:

```text
評価
→ MTU / TCP分割を5問
→ Taskへ反映
→ この内容で次の演習へ
→ Practice Strategy: 弱点補強
→ focus: MTU / TCP分割
→ target: 5問
```

## Persistence

next_stepはStudyPracticeAttempt.assessment JSON内へ保存する。

専用DB columnは追加しない。

理由:

- next_actionは既存互換columnとして維持
- next_stepはassessment schemaの一部
- kindごとの要件が今後変わってもmigration不要

## Existing Reliability Kept

- assessment request hash idempotency
- Task progress never regresses automatically
