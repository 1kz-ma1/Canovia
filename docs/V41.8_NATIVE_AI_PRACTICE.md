# V41.8 Native AI Practice

更新基準: 2026-09-25

## 目的

V41.8は、V41.5のEconomy FoundationとV41.7のAdmin / Premium Experience Foundationを、最初の実際のPremium価値へ接続する。

FreeのAI Practiceを削らず、同じ学習ループの「AIとの受け渡し摩擦」だけをPremium Coreが引き受ける。

```text
Free
  CanoviaでPrompt生成
    -> 外部AIへコピー
    -> JSONをCanoviaへ戻す
    -> Canoviaで回答
    -> 評価Promptを外部AIへコピー
    -> 評価JSONをCanoviaへ戻す

Premium Core
  Canoviaで演習開始
    -> Native AIが問題生成
    -> Canoviaで回答
    -> Native AIが評価
    -> 結果 / Evidence / Next Action
```

原則は「努力する権利には課金しない。努力を加速する価値に課金する」。

## Access boundary

AI Practice本体は引き続きFree。

- `FeatureKey::AiPractice`: Free
- `FeatureKey::QuestionPack`: Free
- `FeatureKey::AutomaticAiExecution`: Premium Core

Native AIを呼ぶ前には必ず `FeatureAccessService` で `AutomaticAiExecution` を判定する。UI上のPremium表示、Product Grantの種類、Admin状態をProviderやControllerへ直接埋め込まない。

Super Admin通常表示ではV41.7の設計どおりNative AIを検証できる。Free PreviewではNative AIを使えず、Premium PreviewではPremium Coreとして利用できる。

## Provider boundary

Study Practiceの既存Provider境界を維持する。

```text
Question source
  - question_bank
  - external_ai
  - native_ai

Assessment source
  - question_bank_grader
  - external_ai
  - native_ai
```

Question Bankで十分にCoverageできる場合は、既存の決定論的なQuestion Bank経路を優先する。Coverage不足時、Premium CoreにはNative AIをPrimary Actionとして提示し、Freeには従来のExternal AI handoffを提示する。

Native AIはProvider設定を `config/native_ai.php` に閉じ込める。V41.8の最初のadapterはOpenAI Responses API向けだが、Study Practice側は直接Provider固有HTTPを扱わない。

## Native AI execution

`NativeAiGateway` は以下を担当する。

- server-side API credential
- structured JSON schema request
- timeout / provider error mapping
- response JSON extraction
- usage token取得
- `native_ai_runs` への実行履歴記録

アプリコードはNative AIの返答をそのまま信用しない。Structured Outputの後でも、Canovia側でflow、Plan ID、Task ID、question schema、score、progress、feedback等を再検証する。

契約不一致はRunをfailedとして記録し、Study Practiceではmanual handoffへfallbackする。

## Safe fallback

Native AIが次の理由で完了しない場合も、AI Practice自体を使えなくしない。

- API key / driver未設定
- timeout / connection failure
- provider 429 / 5xx
- refusal / empty output
- JSON / Canovia contract mismatch
- assessment時の一時障害

問題生成で失敗した場合はExternal AIの問題作成Promptを表示する。

評価で失敗した場合は、回答済み状態を保持したままExternal AIの評価Promptを生成し、従来の評価JSON importへ戻す。

## AI Capacity

EntitlementとAI Capacityは別責務のまま維持する。

```text
Premium Core
  -> Native AIを使えるか

AiCapacityService
  -> どの利用枠で実行するか
```

V41.8ではstandard / boostedをNative AI Runへ記録し、生成・評価のmax output token上限をtier別設定にする。All Accessだけでboostedにはならない。

V41.8では請求額計算、token単価、日次/月次hard quota、購入処理は実装しない。

## Usage history

`native_ai_runs` は将来のコスト制御・quota・運用診断のための最小履歴。

主な項目:

- user / plan / task / study practice session
- FeatureKey / purpose
- provider / model / capacity tier
- status
- provider response id
- input / output / total tokens
- error code / message
- started / completed timestamps
- metadata

Prompt本文やAPI keyはusage historyへ保存しない。

`prepare_request_id` の既存idempotencyをProvider実行前にも適用し、同じ問題準備POSTの再送でNative AIを二重実行しない。

## UI

V41.6 Action First / Progressive Disclosureを維持する。

Premium + Native AI configured:

1. 「Canovia内で演習を準備」をPrimary Action
2. External AI handoffは折りたたみfallback
3. Native失敗時だけfallbackを自動で開く

Free:

1. 既存External AI handoffをPrimary Action
2. Prompt copy / JSON pasteをそのまま利用可能

Premium権利があってもNative AI server configが無効の場合、短い状態説明を出し、Freeと同じmanual pathを使える。

## Configuration

V41.8はNative AIをdefault disabledで導入する。

```env
CANOVIA_NATIVE_AI_DRIVER=disabled
OPENAI_API_KEY=
OPENAI_BASE_URL=https://api.openai.com/v1
CANOVIA_NATIVE_AI_MODEL=gpt-5.6-luna
CANOVIA_NATIVE_AI_TIMEOUT_SECONDS=45
```

API credentialはサーバー側だけに置く。Browser / SwiftUI clientへAPI keyを渡さない。

## V41.8.1 Input UI contract

Native AI / External AIで問題ソースが変わっても、回答UIの学習意図は同じにする。

各AI生成questionは `work_input` を持つ。

- `none`: 用語・定義・単純知識など、最終回答だけで十分
- `reasoning`: 条件整理・比較・アルゴリズム追跡・判断根拠を見る価値がある
- `calculation`: 式・途中値・単位変換・性能/可用性/確率等の計算過程を見る価値がある

`reasoning` / `calculation` では本番形式のanswer fieldを維持したまま、診断用textareaを追加する。textareaは学習時の追加情報であり `required=false` とする。

Providerがwork_inputを返したにもかかわらずtextareaを省略した場合は、Canoviaの共通question normalizationが次を補完する。

- reasoning -> `reasoning` / 「考え方・判断理由」
- calculation -> `calculation_work` / 「計算過程」

この補完はNative AI専用ではなくExternal AI JSON importにも適用する。既存JSONでwork_inputがない場合は、reasoning / calculation系のfieldが既にあればそこから互換推定し、なければ `none` として扱う。


## V41.8.2 Hybrid Question Assembly

Premiumの自動AI演習は「全問Native AI生成」を前提にしない。

```text
Practice Demand
  -> Question Bank partial selection
  -> uncovered seats only
  -> Native AI generation
  -> one mixed exercise
```

Question Bankで十分に賄える場合はNative AIを呼ばない。部分Coverageの場合は、重点弱点 / secondary / diagnosticのrequested mixに対してBankで埋まったbucketを差し引き、不足分だけNative AIへ依頼する。

Native AI Promptには既に選定済みのBank問題の要約を渡し、同じ問いや単純な数値差し替えだけの重複を避ける。

Mixed exerciseのブラウザ向けquestion snapshotには正答を含めない。Native assessmentを使う場合だけ、`source_question_id` からQuestion Bankの `grading_rule` / explanationをserver-side promptへ追加する。

### Practice Demand

`practice_question_demands` は特定資格に依存しない需要/供給履歴。

主な項目:

- user / plan / task / study practice session
- prepare_request_id
- strategy_key / exam_profile_key
- assembly_mode
- generation_provider
- requested_count
- bank_selected_count
- generated_requested_count / generated_count
- focus_topics
- Question Pack / Coverage
- Plan / Taskの最小snapshot metadata

目的は利用者の文章を教材へ直接転用することではなく、「どの学習領域で何問不足しているか」を運営側が判断できるようにすること。

V41.9ではこの履歴をAdminから集計し、Question Bank調達優先度・Candidate問題の検討へ接続する。
