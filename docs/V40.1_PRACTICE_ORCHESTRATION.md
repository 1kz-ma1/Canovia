# V40.1 Practice Orchestration

## Purpose

V40.1 makes AI Practice independent from where AI execution happens.

The user entry point remains:

```
Task
  ↓
AI演習
  ↓
Canovia decides the practice strategy
  ↓
Questions are prepared
  ↓
Answer in Canovia
  ↓
Assessment
  ↓
Learning history
```

Today, question preparation and free-form assessment are handed off to an external AI.

Future versions can replace that handoff with Question Bank selection or an embedded model without changing the Task → AI演習 entry flow.

---

## Responsibility boundary

### Canovia

Canovia owns:

- Plan and Task context
- recent learning history
- weaknesses and misconceptions
- Practice Strategy
- provider routing
- response UI
- deterministic validation
- StudyPracticeSession lifecycle
- StudyPracticeAttempt history
- Task progress application

### AI provider

The AI provider owns:

- selecting/generating questions according to Canovia's strategy
- free-form or reasoning assessment when required

The AI provider must not independently replace Canovia's learning strategy.

### Question Bank

The Question Bank will become the trusted source for:

- question text
- provenance
- answer schema
- grading rule
- learning metadata

## Practice Strategy

`StudyPracticeStrategyService` produces a versioned strategy snapshot.

Current strategies:

- `baseline_assessment`
  - no previous attempts
  - broad understanding check
- `weakness_reinforcement`
  - weaknesses or misconceptions exist
  - prioritizes those concepts
- `retention_and_transfer`
  - recent score is high and no explicit weakness remains
  - focuses on retention and transfer
- `task_mastery`
  - general Task-centered mastery check

The snapshot also contains:

- focus_topics
- target_question_count
- history_sample_count
- latest_score_percent
- Task snapshot
- Plan snapshot

This snapshot is persisted in `StudyPracticeSession.selection_context`.

## Provider contracts

### Question

`StudyPracticeQuestionProvider`

A provider exposes:

- key
- mode
- prepare()

Current provider:

`ExternalAiStudyPracticeQuestionProvider`

Current mode:

`handoff`

### Assessment

`StudyPracticeAssessmentProvider`

Current provider:

`ExternalAiStudyPracticeAssessmentProvider`

### Router

`StudyPracticeProviderRouter` is the only location that decides which provider is used.

V40.1 returns external AI for every Task.

Future logic can become:

```
Question Bank has sufficient trusted coverage?
    YES → QuestionBankProvider
    NO
Embedded AI available?
    YES → EmbeddedAiProvider
    NO  → ExternalAiProvider
```

The controller and UI do not need to know which concrete provider was selected.

## Current UX

V40.1 deliberately does **not** add another user action.

Current flow remains:

1. open AI Practice
2. copy the preparation Prompt
3. send it to the user's normal AI
4. paste returned JSON
5. answer in Canovia
6. copy assessment Prompt
7. paste assessment JSON

The difference is internal:

- Canovia first determines Practice Strategy
- the external AI receives that strategy
- returned questions are attached to a StudyPracticeSession
- assessment is routed through the assessment provider abstraction

When embedded AI arrives, steps 2–4 and 6–7 can disappear without changing the entry point.

## StudyPracticeSession

V40.1 adds `study_practice_sessions`.

A session records:

- plan_id / task_id
- user or browser actor
- session_token
- prepare_request_id
- status
- strategy + version
- selector type + version
- question provider + mode
- assessment provider + mode
- selection_context
- provider_payload
- assessment_payload
- selected_questions
- started_at
- completed_at

### Lifecycle

```
awaiting_provider
      ↓
ready
      ↓
answered
      ↓
assessed
      ↓
completed
```

If the learner resets an unfinished exercise:

```
ready / answered / assessed
      ↓
abandoned
```

Existing V40 browser sessions without a StudyPracticeSession still work through the compatibility fallback.

---

## Why the session exists

It is not only history storage.

It lets Canovia later answer:

- Why were these questions selected?
- Which strategy selected them?
- Which model/provider was used?
- Which question source was used?
- Did the learner improve afterward?
- Does selector v2 outperform selector v1?
- Are AI-generated questions less effective than official Question Bank questions?

This is required before Canovia can safely optimize question selection automatically.

## External AI today, embedded AI later

The semantic role of AI does not change.

### Today

```
Canovia Context
→ Canovia Practice Strategy
→ external AI handoff
→ returned questions
```

### Future

```
Canovia Context
→ Canovia Practice Strategy
→ Provider Router
   ├ Question Bank + embedded selector
   ├ embedded generator
   └ external AI fallback
→ questions
```

The user sees the same AI Practice Tool.

## Deferred to V40.2+

V40.1 does not yet implement:

- actual AP Question Pack content
- Question Bank selection provider
- embedded model API
- deterministic grading from `grading_rule`
- Question Pack coverage scoring
- selector quality dashboards
- qualification support requests
- mobile pack download
- Premium entitlement

The next logical step is a Question Bank provider and AP pack ingestion/admin workflow.
