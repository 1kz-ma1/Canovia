# V39.1 Instant Start Safe Return

## Goal

Restore Instant Start without changing the online mutation path stabilized in V39.0.

## Safety invariants

1. Service Worker never intercepts non-GET requests.
2. Only `/`, `/navigate`, and `/roadmap` navigation requests can receive the local shell.
3. AI JSON, plan creation/update, auth, admin, collaboration invite, and PWA handoff remain normal network requests.
4. The shell resumes the requested page with `_canovia_network=1`, which bypasses the shell decision and prevents loops.
5. The wake-up request continues in the background only for GET navigation.
6. Offline timer sync remains a direct POST to Laravel and is not handled by the Service Worker.
7. A Service Worker failure must not block normal Canovia startup.

## Manual smoke test after deploy

- Open Canovia normally and verify plan creation / AI JSON preview / apply / timer start still behave normally.
- Leave the Render service idle long enough to sleep, then launch the installed PWA. The local Home/Today/Roadmap shell should appear immediately.
- Confirm the shell changes to the live page after `/health` succeeds.
- Open the PWA installation flow again and verify first-launch handoff still transfers the account/Guest context without showing the offline shell.
- Double-submit a critical mutation in a throttled connection and verify V39 idempotency still prevents duplicates.
