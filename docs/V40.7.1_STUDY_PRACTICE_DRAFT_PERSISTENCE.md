# V40.7.1 Study Practice Draft Persistence

## Purpose

AI演習は10問前後の演習を途中で中断することがある。

V40.7以前は、回答内容が「回答をまとめて評価へ進む」を押すまで
StudyPracticeSessionへ保存されず、画面移動・ブラウザ終了などで
入力内容を失う可能性があった。

V40.7.1では、保存ボタンや再開確認を追加せず、
通常の入力そのものを下書き保存として扱う。

## User Experience

### Answering

ユーザーは通常どおり回答する。

```text
入力
↓
端末へ即時保存
↓
短いdebounce後にserver autosave
```

保存ボタンは表示しない。

### Leave / Close

画面移動・tab close・browser close時にも最後の保存を試みる。

通信が間に合わなくても、同一StudyPracticeSessionのlocal draftが残る。

### Resume

同じAI演習を再度開いた場合:

```text
open AI Practice
↓
unfinished StudyPracticeSessionを確認
↓
questions_snapshot + draft_answersを復元
↓
回答画面をそのまま表示
```

「前回の演習を再開しますか？」の確認は表示しない。

## Persistence Layers

### 1. Browser localStorage

Key:

```text
canovia.study-practice.draft.v1.{session_token}
```

Purpose:

- keystroke直後の保護
- debounce前のnavigation
- server autosave failure時のfallback

### 2. StudyPracticeSession

New fields:

- exercise_title
- questions_snapshot
- draft_answers
- draft_saved_at

The DB snapshot is the durable source for normal navigation and PHP Session loss.

## Lifecycle

V40.7.1 adds:

```text
ready
↓
in_progress
↓
answered
↓
assessed
↓
completed
```

Reset:

```text
ready / in_progress / answered / assessed
↓
abandoned
```

Only ready and in_progress sessions are silently resumed as answer drafts.

## Autosave Endpoint

```text
POST /plans/{plan}/tasks/{task}/study-practice/draft
```

Input:

- practice_session_id
- answers_json

The endpoint:

1. checks Plan / Task authorization
2. scopes StudyPracticeSession to the current Account or Guest actor
3. accepts only ready / in_progress
4. validates values against the stored response_fields
5. persists partial answers without requiring all required fields

Final required-field validation remains in submitAnswers().

## Question Snapshot

A resumable session must not depend only on PHP Session state.

Therefore both Question Bank and external-AI exercises persist the normalized question set into:

```text
study_practice_sessions.questions_snapshot
```

This allows the answer UI to be reconstructed after the browser session state is lost.

## Security

Autosave does not weaken ownership checks.

The request must pass:

- FeatureAccess middleware
- Plan / Task authorization
- actor-scoped StudyPracticeSession lookup

A user cannot write draft answers into another actor's Practice Session by supplying its id.

## Reset Semantics

「演習をやり直す」は明示的な破棄操作。

The active unfinished StudyPracticeSession becomes:

```text
abandoned
```

Abandoned sessions are not auto-resumed.

## No New Visible UI

Intentionally not added:

- Save button
- autosave badge
- resume modal
- resume notification
- draft-management screen

The persistence behavior should be invisible unless it prevents data loss.
