# V40.5 Canovia Guide

## Goal

Canovia now has enough functionality that discoverability becomes a product problem.

V40.5 introduces **Canovia Guide**: a reusable in-product navigation system that starts from what the user wants to do, rather than requiring the user to already know a feature name.

This is intentionally broader than a first-run tutorial.

The same Guide Runner can later be launched from:

- Achievement "GO!"
- empty states
- release notes
- feature announcements
- error recovery
- contextual help

The caller only needs a Guide key.

---

## Entry point

### Mobile

The Guide button is placed in the top header immediately before 更新情報.

### Desktop

Guide is exposed in the header utility area.

## Guide definitions

Definitions live in:

`config/canovia_guides.php`

A Guide has:

- key
- category
- title
- description
- keywords
- optional authentication requirement
- start path
- steps

A Step has:

- optional path
- target
- title
- copy
- advance mode

Example conceptually:

```php
'collaboration_create' => [
    'category' => 'together',
    'title' => '共同計画を作って招待する',
    'start_path' => '/roadmap',
    'steps' => [
        [
            'path' => '/roadmap',
            'target' => 'collaboration-settings',
            'advance' => 'click',
        ],
        [
            'target' => 'collaboration-primary',
            'advance' => 'next',
        ],
    ],
],
```

## Stable Guide targets

Guide does not target layout/CSS classes.

Interactive surfaces receive a stable attribute:

```html
data-guide-target="collaboration-settings"
```

The Runner can also reuse existing:

```html
data-onboarding-target="..."
```

This means visual redesigns do not need to rewrite Guide definitions unless the functional control itself changes.

---

## Cross-screen Runner

Guide state is saved before normal navigation.

Storage:

```
canovia.guide.active.v1
canovia.guide.completed.v1
```

For a click Step:

1. target is highlighted
2. user presses the real Canovia control
3. Runner saves the next Step
4. the normal page navigation happens
5. the next screen loads
6. Guide resumes automatically

The Guide does not simulate core product actions.

It teaches by letting the user use the real control.

---

## Spotlight

The Runner uses the same visual language as existing onboarding:

- dim surrounding page
- cyan focus ring
- contextual bubble
- automatic scroll
- bubble placement above/below the target
- 前へ
- 終了
- 次へ / 完了

For click Steps, the Guide asks the learner to press the highlighted product control rather than providing a duplicate "Next" action.

---

## Missing-target safety

A Guide can be started when the required Plan or Task does not exist.

When the expected target is absent:

- no product action is fabricated
- the Runner explains that the target is not currently available
- the user can return to the Guide list

Example:

A user with no Plan can open the collaboration-create Guide, but Canovia will not invent a Plan to continue the tutorial.

## Authentication

Some Guides require an account.

Current examples:

- 共同計画を作って招待する
- 共同計画に参加する

When a guest starts one of these Guides, Canovia redirects to login rather than exposing an unusable flow.

## Collaboration Guide

V40.5 treats collaboration as a first-class Guide category.

### Create / invite flow

```
Roadmap
→ 共同計画にする / 管理
→ 共同計画設定
→ enable
→ invitation URL / join code
```

Guide targets:

- `collaboration-settings`
- `collaboration-primary`

### Join flow

```
計画一覧
→ 共同計画に参加
→ 参加コード
```

Guide targets:

- `collaboration-join`
- `collaboration-code`

Future additions can use the same category:

- member roles
- editor/viewer differences
- removing members
- regenerating invitations
- shared activity history

## Achievement integration

V40.5 exposes:

```js
window.CanoviaGuide.start('study_practice')
```

and supports:

```html
<button data-guide-start="study_practice">GO!</button>
```

A future Achievement system therefore does not need to implement its own navigation tutorial.

Example:

```
Achievement
  tutorial_key = study_practice
      ↓
GO!
      ↓
CanoviaGuide.start(tutorial_key)
```

The Achievement feature can remain decoupled from Guide internals.

---

## Completion state

When the last Step completes, the Guide is marked complete locally.

The Guide list displays:

`✓ 完了`

A completed Guide can still be started again.

This local state is presentation state, not business-critical data.

A future account-synced Achievement system may store achievement completion separately.

No migration.

This avoids coupling the first Guide implementation to accounts or collaboration ownership.
