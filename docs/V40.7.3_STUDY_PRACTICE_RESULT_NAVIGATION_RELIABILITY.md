# V40.7.3 Study Practice Result & Navigation Reliability

## Problem

Production logs showed that some normal Canovia pages were requested twice for a single navigation.

Typical AI Practice sequence:

```text
POST /study-practice/assessment
→ GET /study-practice (result available)
→ GET /study-practice (duplicate navigation)
```

The first GET rendered the assessment result. The immediately-following duplicate GET could consume/overwrite volatile PHP Session state and make the screen look unchanged.

The same duplicate-GET pattern was observed on other normal pages such as WorkSession.

## Root Cause

`public/sw.js` enabled Service Worker Navigation Preload globally:

```js
self.registration.navigationPreload.enable()
```

However `event.preloadResponse` was consumed only for the Instant Start allowlist:

- /
- /navigate
- /roadmap

All other navigations intentionally bypassed the Service Worker.

Navigation Preload is registration-wide, not route-scoped. This meant network-only routes could receive:

1. an unused preload request
2. the browser's normal navigation request

That violated the intended rule that AI/import/auth/admin routes bypass Service Worker navigation handling.

## Fix 1: Disable Navigation Preload

V40.7.3 changes activation to:

```js
self.registration.navigationPreload.disable()
```

Instant Start still performs its own network request and retains its offline-shell fallback.

This prioritizes correctness over the small wake-up optimization provided by preload.

## Fix 2: Durable AI Practice Recovery

StudyPracticeSession already persists:

- questions_snapshot
- draft_answers
- assessment_payload
- status

StudyPracticeAttempt persists:

- questions
- answers
- assessment
- score
- weaknesses
- recommended progress
- next action

V40.7.3 uses those durable records to recover unfinished stages.

Recoverable states:

```text
ready
in_progress
answered
assessed
```

### answered

Canovia reconstructs:

- questions
- final answer snapshot from durable draft answers
- evaluation Prompt from StudyPracticeSession.assessment_payload

The learner can continue to return the assessment JSON even after PHP Session loss.

### assessed

Canovia restores the latest StudyPracticeAttempt for the StudyPracticeSession and displays the assessment preview again.

The learner does not need to re-submit the AI assessment just because a page/session race occurred.

## Fix 3: Reveal the Next Step

After successful mutations, Canovia stores a one-shot scroll target:

- problem JSON import → `practice-questions`
- answer submit → `practice-evaluation`
- assessment JSON import → `practice-assessment`

The Study Practice page scrolls to the newly available section.

This prevents a successful same-page redirect from feeling inert.

## Service Worker Boundary

The V39.1 allowlist remains unchanged.

Instant Start:

- /
- /navigate
- /roadmap

Network-only:

- AI Practice
- Plan AI imports
- Auth
- Admin
- PWA handoff
- Plan detail
- WorkSession
- other mutations/sensitive routes
