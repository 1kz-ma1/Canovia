# V39.5 Dashboard Guidance Deck

## Purpose

Home answers three different questions through three separate layers.

1. **Guidance Deck — What should I do?**
2. **RecommendationService — How should I approach it right now?**
3. **Canovia Tools — What tool should I use to execute it?**

The important boundary is that behavioral personalization must not replace an objectively higher-priority Task on Home.

## Objective selection

### Plan order

Plans are ordered by:

1. `plans.priority` ascending (1 is highest)
2. deadline ascending
3. Plan id ascending

Existing Plans receive priority `3` through the migration default.

### Task selection inside each Plan

Only executable Tasks are considered.

Excluded:

- `done`
- `cancelled`
- progress >= 100
- prerequisite Task not done
- remaining minutes <= 0

Remaining Tasks are ordered by:

1. Task priority ascending
2. `doing` before `todo`
3. `sort_order`
4. Task id

This selection lives in `DashboardGuidanceService`, not `RecommendationService`.

## Adaptive advice

After the objective Task is selected, `RecommendationService` is called with
`candidateTaskIds` containing only that Task.

It may calculate:

- recommended work duration
- time fit
- readiness / activation fit
- continuation context
- explanatory reasons

It cannot replace the Guidance Task.

The existing Navigation flow continues to use the adaptive RecommendationService normally and may choose among Tasks there.

## Tool recommendation

`PlanToolService` receives the selected Plan and Task.

The Home card prefers a recommended specialized Tool over the generic timer when both are recommended.

Examples:

- qualification-study practice Task -> AI Practice
- implementation Task -> Project Artifacts
- otherwise -> normal Task start / timer

Tool selection assists execution and never controls objective Task selection.

## UI

Home renders one Guidance card per editable Plan.

- first card = highest-priority Plan
- horizontal swipe = other Plans
- each card displays Plan priority, Task priority and Task status
- adaptive advice is visually separated as "Canoviaの提案"
- specialized Tool actions are available directly from the card
- normal Task start remains available

The legacy `dashboard['recommendation']` key remains as a compatibility alias to the adaptive advice for the first Guidance Task. It must not point to a different Task.

## Plan priority

`plans.priority` is an integer from 1 to 5.

- 1 = highest
- 5 = lowest
- default = 3

It is user-controlled because priority is a decision about the user's goals, not something Canovia should infer from behavioral data.

Plan update requests that omit priority preserve the existing value for backward compatibility.

## Deployment

Render startup runs:

`php artisan migrate --force`

before production caches and Supervisor startup, so the `plans.priority` migration is applied before the new code serves requests.
