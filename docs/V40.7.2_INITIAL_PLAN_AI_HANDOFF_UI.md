# V40.7.2 Initial Plan AI Handoff UI

## Goal

初期計画作成だけに残っていた旧式の外部AI受け渡しUIを、Canoviaの現在のAI Handoff contractへ統一する。

V40.4 / V40.4.3以降、AI演習・計画更新・Policy Change・Resource Assistantでは、raw Prompt / raw JSONを通常の視覚階層から外している。

V40.7.2では初期計画作成も同じ原則へ揃える。

## Before

初期計画画面では通常表示として次が残っていた。

- 360px級のraw Prompt textarea
- 320px級のraw JSON textarea
- 個別実装のclipboard copy JavaScript
- JSON repair Promptの大きなtextarea
- 他の現行Canovia画面と異なるlight-tone系の旧カード表現

## After

### Step 1: AIへ渡す

Normal view:

```text
[相談文をコピー]
[この相談文に含まれる情報 ▼]
```

Raw Promptは `sr-only` で保持し、server generated Promptそのものをcopy targetにする。

Prompt summary:

- 対象PlanのID・基本情報
- AI共有対象のFuture Memo
- Task分解時の時間・優先度・順序ルール
- JSON schema / authoritative Plan ID safety rule

### Step 2: Canoviaへ戻す

Normal view:

```text
[クリップボードから貼り付けて読み込む]
[手動で貼り付ける / JSONを確認する ▼]
```

Supported browser:

1. clipboard read
2. `tasks_json` へ設定
3. existing formをnative submit
4. existing server-side normalizer / validatorが処理

Clipboard read unavailable:

1. manual detailsをopen
2. textareaへfocus
3. userがmanual paste
4. existing submit buttonで処理

## Important reliability constraint

Initial Plan JSON importはV38.7以降、critical importとしてserver-ownedである。

Therefore V40.7.2 does **not** add a client JSON parser or asynchronous mutation.

Existing form marker is preserved:

```html
data-ai-plan-generation-import
```

`resources/js/app.js` はこのformについてnative POSTを妨げない。

## Funnel telemetry

Existing telemetry remains:

- plan_generation_opened
- plan_generation_prompt_copy_clicked
- plan_generation_import_attempted
- plan_generation_import_succeeded
- plan_generation_import_failed

Prompt copy keeps:

```html
data-funnel-event="plan_generation_prompt_copy_clicked"
```

No Prompt or JSON body is added to telemetry.

## Repair flow

When server validation returns a `tasks_json` error:

- pasted input remains available in manual JSON details
- raw repair Prompt is hidden from the normal hierarchy
- user sees the detected error
- user can copy the repair request with one action
- collapsed details explain what the repair request contains

The repair Prompt continues to include:

- server error
- failed JSON
- original Canovia Prompt
- authoritative Plan ID
- formatting constraints

## Visual layout

Desktop:

```text
[ AIへ渡す ] [ Canoviaへ戻す ]
```

Mobile:

```text
[ AIへ渡す ]
[ Canoviaへ戻す ]
```

The surrounding page now uses the current dark `page-card` visual language.

## Unchanged

No changes to:

- Prompt semantics
- JSON schema
- AiTaskAssistantController
- server-side normalization
- Plan ID safety checks
- task creation semantics
- mutation idempotency
- Future Memo inclusion rules
- onboarding target names
- funnel event meanings
