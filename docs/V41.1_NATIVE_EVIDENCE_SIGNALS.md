# V41.1 Native Evidence Signals

## Goal

V41.0で追加したTask Evidence基盤を、AI Practiceだけの専用経路にせず、
Canoviaが既に観測できる実行事実へ広げる。

V41.1では外部OAuthやAI解析を追加せず、現在のCanoviaだけで確実に取得できるSignalを優先する。

## Added Evidence

### 1. AI Practice

V41.0から継続。

- type: `study_practice_assessed`
- confidence: 1.0
- progress policy: high-confidence Evidenceとして、ユーザー確認後のTask反映に利用可能

### 2. Artifact state

Taskへ明示的に紐づけられた制作ファイル・リポジトリ・フォルダ・リンクをCanovia上で登録または更新した場合に記録する。

- type: `artifact_state_observed`
- source: `native`
- confidence: 0.8
- metadata:
  - artifact id
  - title
  - provider
  - artifact type
  - URL
  - version label
  - created / updated

同じArtifact stateはhashからexternal_keyを生成し、同一状態の二重記録を防ぐ。

Artifactの存在・更新は強いSignalだが、「Task完了」を直接意味しないため、V41.1ではprogressを自動変更しない。

### 3. Focus Timer activity

オンライン・オフライン双方のFocus Timer終了をEvidenceへ変換する。

- completed: `focus_session_completed`, confidence 0.4
- interrupted: `focus_session_interrupted`, confidence 0.25

metadataにはactual / active / wall / paused time等を保持する。

時間は「取り組んだ事実」の補助Signalであり、成果の証明ではない。
そのためEvidenceProgressServiceのprogress recommendation対象にはしない。

## Plan Hub visibility

CURRENT TASKに最近のEvidenceを最大3件表示する。

UI上は「進捗の証拠」と断定せず、**Canoviaが確認できた事実**として表示する。

例:

```text
RECENT EVIDENCE

AI演習
Canovia · 5分前
AI演習 90% · 10問中9問正解

制作ファイル
Canovia · 1時間前
「発表資料 v2」を更新しました

集中作業
Canovia · 2時間前
集中タイマーで25分取り組みました
時間は進捗ではなく補助情報です
```

## Why not Resource views?

資料を開いたことだけでは、読んだ・理解した・Taskが進んだとは判断できない。
V41.1ではResource閲覧をEvidenceとして自動記録しない。

## Remaining work

V41.1後も以下は持ち越し。

1. GitHub API / Webhookからcommit・PR・mergeを直接取得
2. Drive / OneDrive / Dropbox等の外部ファイル変更検知
3. ローカルフォルダ監視
4. 写真EvidenceのアップロードとAI解析
5. Calendar予定・結果のEvidence化
6. EvidenceからTaskMilestone達成を判定
7. Milestone / Evidenceからprogressを自動算出
8. Evidence変化を受けたPlan最適化
9. AIがEvidenceを意味解釈してNext Actionを再生成

これらは `ExecutionAdapter -> TaskEvidence -> EvidenceProgressService / TaskMilestone`
の既存境界上へ追加する。
